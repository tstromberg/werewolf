# Arbitrary-code-execution audit — 2026-10-14

Scope: a static red-team read of the working tree (uncommitted capability
drops in `slot-update`, `stage0` and `lib/broker.zig` included) along five
surfaces, each read in full by one reviewer and the load-bearing claims
re-read by the lead: the update path (`cmd/slot-update`, `lib/apk.zig`,
`lib/prebuilt.zig`, `lib/boot-authority.zig`, the broker's staged-file
path); network-facing root parsers (`cmd/dhcp-client`, `cmd/cloud-metadata`,
`lib/people.zig`, `lib/tpm*.zig`, `lib/enrollment.zig`, `lib/cmdline.zig`);
the boot core (`cmd/stage0`, `cmd/init`, `cmd/mount-broker`, `cmd/mount`,
`cmd/slot-keep`); the confinement layers (`lib/seal.zig`, `cmd/leash`,
`cmd/fence`, `cmd/sh-shim`, `lib/sandbox.zig`); and the host side
(`cmd/howl`, `lib/form.zig`, `lib/compose.zig`, `tools/`). Every fix claimed
by [privilege-separation.md](../design/implemented/privilege-separation.md) and
[muse-root-ace-2026-10-13.md](muse-root-ace-2026-10-13.md) was checked
against code. Nothing was executed on a machine during the read.

The attacker modelled: root inside the fence. Since sshd moved under leash
it keeps `login_set` (`lib/service.zig:102` — CHOWN, DAC_OVERRIDE, KILL,
SETUID, SYS_CHROOT, SYS_BOOT…) and a bind-only Landlock ruleset
(`cmd/leash/leash.zig:258,266`), so a root SSH session's file access is
exactly the fence's: `/run`, `/tmp`, `/var/tmp`, `/dev/shm` and `/data`
writable (`cmd/fence/fence.zig:887-893`), with modes no obstacle. The same
holds for the daemons runit starts without leash (`autoupdate`,
`slot-keep`, `cloud-metadata`, `posture`, `power-button`).

## TL;DR

No new memory-safety bug and no direct code-execution path was found in
the guest's root parsers: DHCP, metadata HTTP and tar, APKINDEX and
`.PKGINFO`, the broker's request words, the TPM capsule, the kernel command
line and the config tar all held under reading, and the muse/argon fixes
are present (one exception, F2). The seal is default-deny on both ABIs, the
leash drop order is right, and sh-shim refuses everything but a plain word
list.

What remains are two design-level gaps where confined root on a
*locally built* slot can still shape the next boot (F1, F3), one
documented control that was never built (F2), and — the one new integrity
break — a build-time policy injection on the host: an OCI image's
`WorkingDir` is rendered into its service file unchecked (F4). The rest is
small hardening and prose that promises more than the code enforces.

### F1 — A locally built slot is authenticated against the tree it was built in

For signed images the updater names the signed manifest's digests and the
broker verifies the staged bytes against them — sound. For local builds
(`u.image == null`: no IPE marker, `cmd/slot-update/slot-update.zig:982`)
`installEsp` hashes whatever sits in `/data/svc/autoupdate/work/slot/`
(`cmd/slot-update/slot.zig:317,360-368`) and the broker checks only that
the file matches *those* digests (`cmd/mount-broker/mount-broker.zig:757-878`).
apk signatures are checked on download, but the extracted tree, the cpio,
the erofs and the staged files all live on `/data`, which every fenced root
process may write. Between `apkAdd` and `hashFile` — minutes, and
`check` on the control socket opens the window on demand (F3) — root can
edit `work/root`, `work/stage0/init` or the staged `stage0.zst`; the
updater then names the attacker's digest and the broker installs it. The
next boot runs that initramfs as PID 1 before dm-verity, IPE or any fence
exists; systemd-boot does not verify an initrd, so Secure Boot without a
UKI does not help. This is argon 3.1 / P1, recorded as open; the
privilege-separation redesign did not reach it.

Scope: IPE machines never take this path — `requireLocalUpdate`
(`slot-update.zig:972`) holds them with `IpeSignedImageRequired`, and they
install only signed slots — so `howl run`/`create` on Lima or QEMU, with or
without `--build`, is not affected. Every other machine is: `howl`'s
`requireProtection` (`cmd/howl/howl.zig:1316`) refuses a protected
deployment anywhere but Lima and QEMU, so GCP, AWS, Azure, bhyve,
Firecracker and Proxmox machines are all made with `--insecure` (since
2026-10-15, `--disable=secureboot,tpm,ipe`), non-IPE, and rebuild their
slots in the guest.

An IPE machine cannot rebuild in the guest by design: its policy names one root hash
and is signed by a key that never reaches a machine
([ipe.md](../design/implemented/ipe.md)); a machine able to authorize its own new
root could be made to authorize root's.

The broker's check cannot fix this alone: the tree must be unreachable by
fenced root. Options, in order of preference: (a) argon's — a dedicated
uid and a private mount namespace with a tmpfs work tree for
`slot-update`, set up by init before the fence (Landlock forbids mount
after it); (b) have the broker lend a detached tmpfs over `SCM_RIGHTS`;
(c) declare in local-build forms' `weaknesses:` that root persists across
reboot, and keep the posture `skip` from reading as coverage.

### F2 — The `/run/werewolf` lock from privilege-separation §2 was not built

The design says init bind-mounts `/run/werewolf` read-only after seeding,
writers move to `keep/`, `update/`, `posture/`, `network/`, fence grants
only those, and posture checks the lock. In the tree: no remount of
`/run/werewolf` (`cmd/init/kernel.zig:91-111` only mkdirs it), fence grants
all of `/run` (`fence.zig:887`), `committed` is `/run/werewolf/committed`
(`cmd/slot-keep/slot-keep.zig:13`, `cmd/stage0/stage0.zig:347`), the
control socket and `updater-ready` sit beside it, posture has no check.
Effects for fenced root: `touch /run/werewolf/committed` disarms stage0's
deadman during a trial boot; `touch /run/werewolf/nodata` forces a
rollback on every trial boot; `/run/werewolf/{passwd,shadow,keys/root}` are
rewritable, which `privilege-separation.md:106` says they are not.

The design as written also cannot be built as is: `cloud-metadata` writes
`passwd`, `group`, `shadow`, `people` and `keys/*` after hand-over
(`cmd/cloud-metadata/cloud-metadata.zig:215-250`), which the doc's table
omits. Two shapes work: (a) make only the boot markers unforgeable —
`slot-keep` already holds the keeper channel, so the broker can write
`keep/committed` on a tmpfs it holds a private writable clone of while
the attached mount is read-only, and stage0 reads `keep/committed`; or
(b) the full lock, which needs cloud-metadata's writes to go through init
or the broker. (a) is small and closes the deadman and rollback forgeries;
(b) is the privilege separation the doc describes. Until one lands the
section should say "proposed".

### F3 — Operator `try` is any uid 0, skips the freshness floor, and `bad` lives on `/data`

`cmd/slot-update/control.zig:66` admits any `SO_PEERCRED` uid 0; Landlock
does not mediate `connect` on a named socket, so a root SSH session
qualifies. `try` runs `tryOther`, whose `verifyOther(..., rollback=true)`
skips the serial floor (`cmd/slot-update/images.zig:175`); the only other
gate, `isBad`, reads `/data/svc/autoupdate/bad`, which the same root may
append to, pinning the machine on the older release. The operator is root
by design here, so `try` itself is intended; what is not is that a
compromised root service is indistinguishable from the operator, and that
the anti-rollback record is attacker-writable. Keep `try`; move `bad` and
the floor to the broker's detached `/boot` (a digest-checked
`slot-state`-style word), and consider requiring `committed` to be the
broker's (F2a) before honouring `try`.

### F4 — An OCI image's `WorkingDir` becomes service directives (fixed)

`cmd/howl/oci.zig:98` copies `WorkingDir` from `crane config` unchecked into the
image record; `lib/form.zig:1453-1454` renders it as `dir {s}` where `argv` and `env`
on the lines around it are refused for a quote or `\n\r\t`. `lib/service.zig:193`
splits the rendered file on newlines, so a `WorkingDir` of `/app\nconnect any\nsecret
X /run/config/…` adds lines the form's author never wrote; duplicates of
`user`/`dir`/`root` are refused downstream, but `connect`, `secret`, `config`,
`read`, `write`, `run`, `env`, `before`, `group` are not. A tag is re-resolved on
every build (`oci.zig:593`), so a pushed image changes a signed image's policy, and
the updater re-renders from the same record. Contradicts
[adhoc.md](../design/implemented/adhoc.md) ("nothing an image … says becomes
policy"). Fix: `render` refuses a `workdir` that is not a clean absolute path of
plain printable bytes, with the same test the words get.

### F5 — Published form packages unpack through symbolic links (fixed)

`cmd/howl/published.zig:233-271` checks each name with `clean` but creates
files with `writeFile`, which follows a link at the final component or in
any parent, and creates links with unrestricted targets. A package carrying
`form.yaml -> /some/path` then a regular `form.yaml` writes the second
entry's bytes to the link's target as the developer. Reachable only past
the signed index (a publisher-key holder), so defence in depth, and the
function's own contract says "a name that would leave dir is refused".
`cmd/howl/oci.zig` already does this right (`throughNoLink`, exclusive
create); the fix reuses it.

### F6 — Local TPM sockets in a predictable `/tmp` directory (fixed)

`cmd/howl/local-secure.zig:1630` names `/tmp/ww-tpm-<sha256 prefix>` from
the machine directory; `tools/local-tpm` `serve` refuses a directory that
is a link, another uid's, or not 0700, but `start` and `stop` only connect
to `service.sock` there and trust `OK`. On a shared host another user can
pre-create the directory with sockets of their own and QEMU talks to their
TPM. Fix: `start`/`stop` apply `serve`'s check before connecting.

### F7 — init chmods through `/data` links before the fence (fixed)

`cmd/init/oci.zig:68,97-98,142,154,173,230,236` and `Machine.mkdirAll`
(`cmd/init/init.zig:371`) call `fchmodat(AT_FDCWD, path, mode)` on paths
under `/data/svc/NAME` and `/data/share`; the raw syscall follows links,
and `/data` is mounted `symfollow`. A link planted by root in one boot is
followed by unconfined PID 1 in the next — a chmod of its choosing. `own`
already uses `AT_SYMLINK_NOFOLLOW` and `cmd/mount` refuses the bind, so no
privilege gain was constructed. Fix: `fchmodat2(..., AT_SYMLINK_NOFOLLOW)`
(Linux 6.6+; the kernel here is 6.18).

### F8 — Guest-shaped strings used without the checks their siblings get (fixed)

The Lima lease address (`cmd/howl/lima.zig:224`) is whatever follows
`ip_address=` and reaches `ssh root@{s}`; `proxmox.zig:379` validates the
same kind of text with `isIp4`. `services.NAME.image` in form.yaml is only
checked for whitespace (`lib/form.zig:798`) while the adhoc path requires
`oci.isRef`. Both now use the stricter check.

### F9 — Interactive QEMU console (accepted)

`cmd/howl/qemu.zig:331-338` writes guest bytes to a raw-mode terminal; the
log tail goes through `inert`. Inherent to a console; noted so the
operator knows a compromised guest can emit OSC/DCS at them.

### F10 — Prose stronger than the code

- [pledge.md](../design/implemented/pledge.md),
  [narrow.md](../design/implemented/narrow.md) and `docs/forms.md` say a service
  without `exec` "cannot run a program" / "runs only itself". Landlock EXECUTE and
  the `exec` promise judge `execve`; the PT_INTERP loader must stay executable
  (`cmd/leash/leash.zig:822-841`) and a readable ELF on `/usr` can be mapped and run
  without `execve`. `cmd/leash/README.md` says this honestly; IPE is the backstop.
  Confinement is "same domain, any in-image binary", and the docs should say so.
- [privilege-separation.md](../design/implemented/privilege-separation.md) §2 (F2)
  and §4's DHCP item: the code does not reject `169.254/16` routes, and
  should not as written — GCP's DHCP server and resolver *are*
  `169.254.169.254` (`cmd/dhcp-client/dhcp-client.zig:1470`,
  `lib/dns.zig:105`), and a rogue DHCP server already owns the default
  route, so a host-route check adds nothing. Drop the item.
- §4 says `compose.lay` "refuses symlinks"; `lib/compose.zig:261-267`
  copies links as links and refuses laying through a non-directory, which
  is the property that matters.
- [script-argv.md](../design/retired/script-argv.md): "not built" is accurate;
  forms pledging `exec` with an interpreter should name it in `weaknesses:`.

## Held

Update path — signature before parse everywhere (`lib/apk.zig:91-127`,
`lib/prebuilt.zig`, `tiers.zig`), trailing data refused, duplicate
APKINDEX/`.PKGINFO` refused, malformed versions sort below every real one
(`cve.zig` `minInt`), broker staged files opened `RESOLVE_BENEATH |
RESOLVE_NO_SYMLINKS`, `S_IFREG`, nlink 1, hashed in one pass, renamed on
match, `c=` required (`mount-broker.zig:679-878`), no `esp`/`victim` word,
roles are inherited descriptors, `move_mount` absent from the broker's
filter, updater children `closeAllBut` and drop to uid 69.

Network — DHCP option, route and IP/UDP bounds (`dhcp-client.zig:1182-1350`),
BPF filter locked before bind, xid/chaddr/server match, lease re-validated
by the parent; engine chrooted and sealed to two descriptors; metadata
fetcher chrooted with Landlock connect:80 only, bounded chunked bodies,
header injection refused, GCP keys cannot name root; config tar names via
`entryName`, 32×32 KiB; TPM responses length-checked, EK pinned, replay
refused; `cmdline.parse` strict with coupled invariants; stage0 passes
init only `WEREWOLF_BOOT`.

Boot core — init keeps client ends CLOEXEC until the final `dup2`, stage 2
closes 62, every non-broker entry point closes fds ≥ 3; `/run`, `/tmp`,
`/data` `nosuid,nodev,noexec`; `/boot` `ro,nosymfollow` or init exits;
`cmd/mount` resolves with `RESOLVE_NO_SYMLINKS` and only tightens; IPE
policy compared exactly, `CAP_MAC_ADMIN` dropped before any fork; deadman
child sealed to eleven calls (uncommitted).

Confinement — seal default-deny, foreign arch and x32 killed, `never` list
honoured by every promise, arg checks on socket/setsockopt/pipe2/shmat/
seccomp/syslog, TSYNC install; leash drop order and `StillRoot` check,
config copies `O_EXCL|O_NOFOLLOW` after the drop, `LD_*` stripped; sh-shim
`AT_SECURE` refusal, only `-c [--] WORD...`, fuzzed against `/bin/sh`;
fence default-deny both ways, metadata only by named uid.

Host — `oci.zig` unpack (`clean`, `throughNoLink`, exclusive create, modes
forced, hardlink source checked), machine and form name grammars,
`howl ssh` destination always `root@`, per-machine known-hosts,
`inert()` on every log tail, protected downloads HTTPS-only with streamed
size/digest checks, signing keys by path never argv, apko pinned to the
lock, melange recipes never from a fetched form package, CI workflow
push/schedule only with `persist-credentials: false` and the boot key
confined to `release`-environment jobs behind `with-boot-key`.

## Remediation status

F4–F8 fixed in this pass: `lib/form.zig` refuses a working directory with
a space, quote, control byte or relative path and checks `image` with the
grammar `isImageRef` (moved there from `cmd/howl/oci.zig`);
`cmd/howl/published.zig` unpacks into a `Dir`, refuses a name through a
link with `oci.throughNoLink`, and creates files exclusively after
removing what was there; `tools/local-tpm` checks the socket directory
before every request; `cmd/init` uses `fchmodat2(AT_SYMLINK_NOFOLLOW)`;
`howl.isIp4` now guards the Lima lease. Verified by new unit tests
(`form.zig` "an image's working directory…", `published.zig` "unpack
keeps a form's links…", `lima.zig` `lease` with a flag-shaped address):
`make _test/lib/form.zig` 23/23, `make _test/cmd/howl/howl.zig` 141/141,
`make _test/cmd/init/init.zig` 17/17, `test/howl-test`, `make lint`; and
`howl run --build` booted the playground from these sources under QEMU
Secure Boot, IPE and TPM A/B in 64 s with posture 90 pass / 6 fail /
3 skip, every failure a declared weakness of the form, none unexpected,
and `/run/werewolf/{passwd,shadow,group}` at 644/600/644 on kernel
6.18.56.

F1 is accepted, on the owner's decision (2026-10-15): a machine made without IPE
builds its next slot where root can write it, and that is now what `--disable=ipe`
openly gives up rather than a side effect of a mode. `--insecure` and `--secure` are
gone; `--disable=secureboot,tpm,ipe` names each protection given up (all three
together until one profile stops providing them as one), the slot command line
records what the image lacks (`werewolf.disable`, which stage0 and every reader parse
in `lib/cmdline.zig`: secureboot needs tpm, and neither may contradict
`werewolf.secure` or `werewolf.tpm`), and posture reports it and writes it into the
login message
([security.md](../security.md#protections-a-machine-can-be-made-without)). Posture's
new `processes-no-root-console` fails while root has a console shell without a
password, on werewolf or any Linux.

F2 and F3 stay open as marginal: root inside the fence can already stop the
updater with `sv down`. F9 accepted. F10's privilege-separation.md edits wait
on F2, since §2 describes what its fix would choose.
