# Werewolf Security Audit (Theo de Raadt Lens)

Editorial update, 2026-10-13: findings specific to removed deployment code
have been omitted. Remaining findings and source locations describe the
audited revision; original finding numbers are retained.

- **Audit date:** 2026-10-13 (saved as `argon-2023-10-13.md`)
- **Auditor:** Gemini 4 Argon
- **Scope:** Full repository source (`cmd/`, `lib/`, `tools/`), build/disk pipelines,
  and live runtime inspection of the local VM via `howl ssh`.
- **Lens:** Theo de Raadt / OpenBSD proactive security philosophy — strict privilege
  separation, unforgeable kernel primitives over userland heuristics, elimination of
  attack surface and complexity, fail-closed error handling, and zero tolerance for
  security theatre or marketing overclaims.

---

## Executive Verdict

First, credit where it is due: the core kernel-hardening and sandboxing primitives in
`cmd/init/kernel.zig`, `cmd/seal/seal.zig`, `cmd/fence/fence.zig`,
`cmd/leash/leash.zig`, and `cmd/task-links/task-links.zig` are miles ahead of standard
Linux distributions. Using EROFS + `dm-verity` + IPE, enforcing
`PR_MDWE_REFUSE_EXEC_GAIN`, locking down `/proc/sys` via Landlock instead of trusting
root not to touch sysctls, and confining `task-links` to `read(0)`, `write(0)`,
`readlinkat(AT_FDCWD, ...)`, and `exit_group` is real systems engineering.

Now the cold water:

1. **Stop calling it "unhackable" (`README.md:5`).** When you claim a system is
   "unhackable" and that "not even root can remove" its protections, you set the
   security boundary at **confined root (`uid 0` inside `fence`)**. Yet your runtime
   architecture treats `uid 0` as a single shared principal across `sshd`, `runsvdir`,
   `slot-update`, `slot-keep`, `cloud-metadata`, and interactive root shells—all running
   without `leash`, holding `CAP_DAC_OVERRIDE`, `CAP_KILL`, `CAP_CHOWN`, `CAP_SETUID`,
   `CAP_SYS_CHROOT`, and sharing writable `/run` and `/data`.
2. **You are bolting `/proc/<pid>` scraping heuristics onto a shared UNIX socket instead
   of doing real privilege separation.** When `docs/audit/root-ace-2026-10-13.md` showed
   that confined root could talk to `mount-broker`, the fix added `authorizeService` to
   scrape `/proc/<pid>/{exe,cmdline,cwd,status}` after `SO_PEERCRED`. In OpenBSD, we do
   not put a privileged socket in a shared directory and guess who connected by reading
   mutable process metadata out of `/proc`—the parent creates an anonymous
   `socketpair(2)` before `fork`/`exec` so only the intended child *has* the file
   descriptor.
3. **Code vs. Reality drift already exists on the running VM.** Connecting via `howl
   ssh` immediately revealed that critical boot-state and manifest files on `/victim`
   (`/victim/werewolf/boot-state/state.0`,
   `/victim/werewolf/a/{cmdline,image.json,image.json.sig}`) are owned by the host
   builder's macOS UID/GID (`501:20`, which maps to the unprivileged user `t` inside the
   guest!) because a hardcoded 3-element array in `cmd/howl/disk.zig:301` was not
   updated when new files were added.

## 1. Broken Privilege Separation & IPC Authentication (`mount-broker` & `slot-update`)

### 1.1 `mount-broker`'s `/proc/<pid>` caller authentication is bypassable
- **Severity:** Critical
- **Location:** `cmd/mount-broker/mount-broker.zig:132-225` (`accept`, `heard`),
  `541-586` (`authorizeService`), `613-645` (`serviceIdentity`, `procText*`), `720-780`
  (`procStart`, `identityMatches`)

To prevent confined root from talking to `/run/werewolf/mount-broker.sock`, the broker
checks `c.pid` (captured via `SO_PEERCRED` in `accept`) when a request line arrives in
`heard`. This design has six independent flaws:

1. **`SO_PEERCRED` pins the `connect(2)` caller, not the `write(2)` caller (FD
   inheritance / post-connect `execve`):**
   - In Linux, `SO_PEERCRED` latches the PID of the process that called `connect(2)`.
     That `c.pid` never changes when the socket FD is inherited across `fork(2)` or kept
     open across `execve(2)`.
   - `authorizeService(log, c.pid, service)` is not called in `accept()`; it is called
     later in `heard()` when a newline-terminated command is read.
   - A confined root process can spawn a parent `P` and child `X`:
     - `P` creates a dummy directory `/run/autoupdate` and `execve`s `/usr/bin/runsv`
       with `argv = ["runsv", "autoupdate"]` (Fence grants `EXECUTE` on `/usr`).
     - `X` connects `sock_fd` to `/run/werewolf/mount-broker.sock` (fixing `c.pid = X`),
       forks a child `Y` that inherits `sock_fd`, `chdir`s to `/etc/sv/autoupdate`, and
       `execve`s `/usr/lib/werewolf/slot-update` with `argv = ["./run"]`.
     - Once `X` has transformed into `/usr/lib/werewolf/slot-update`, `Y` writes any
       broker command (`esp-install`, `slot-root`, `victim`, etc.) to `sock_fd`.
     - When `mount-broker` runs `authorizeService(log, c.pid, .updater)`, it inspects
       `X` (`c.pid`) and its parent `P` (`ppid`):
       - `X`'s `exe` is `/usr/lib/werewolf/slot-update`, `cwd` is `/etc/sv/autoupdate`,
         `arg0` is `./run`, `args` is `1`.
       - `P`'s `exe` is `/usr/bin/runsv`, `arg0` is `runsv`, `arg1` is `autoupdate`,
         `args` is `2`.
       - `pidfd_open(X)` succeeds and `procStart(X)` before and after `serviceIdentity`
         is identical (`execve` does not alter field 22 `starttime` in
         `/proc/<pid>/stat`, and `X` has already `execve`d before `Y` writes).
   - Even without forking `Y`, `X` can write its request into the kernel UNIX stream
     socket buffer immediately before calling `execve("/usr/lib/werewolf/slot-update",
     ["./run"], ...)`.

2. **Buffer-aliasing TOCTOU bug in `procText`, `procText2`, and `procText3`
   (`613-645`):**
   ```zig
   return identityMatches(
       service,
       procLink(pid, "exe", &exe_buf) orelse return false,
       procArg(procText(pid, "cmdline", &cmd_buf) orelse return false, 0),
       procArgs(procText2(pid, "cmdline", &cmd_buf) orelse return false),
       procLink(pid, "cwd", &cwd_buf) orelse return false,
       procLink(ppid, "exe", &pe_buf) orelse return false,
       procArg(procText(ppid, "cmdline", &pc_buf) orelse return false, 0),
       procArg(procText2(ppid, "cmdline", &pc_buf) orelse return false, 1),
       procArgs(procText3(ppid, "cmdline", &pc_buf) orelse return false),
   );
   ```
   ```zig
   // procText, procText2 and procText3 read the same file into the same
   // buffer; they exist so a caller can take several slices of one read in
   // one expression without the buffer being refilled between them. Each
   // returns the same bytes.
   fn procText(pid: i32, name: []const u8, buf: []u8) ?[]const u8 {
       return procRead(pid, name, buf);
   }
   fn procText2(pid: i32, name: []const u8, buf: []u8) ?[]const u8 {
       return procRead(pid, name, buf);
   }
   fn procText3(pid: i32, name: []const u8, buf: []u8) ?[]const u8 {
       return procRead(pid, name, buf);
   }
   ```
   The comment claims they exist *"without the buffer being refilled between them"*, yet
   **each function calls `procRead` again on the same `cmd_buf` / `pc_buf`!**
   `procArg(procText(...), 0)` returns a slice pointing into `cmd_buf`, and then
   `procText2` immediately re-opens `/proc/<pid>/cmdline` and overwrites `cmd_buf`
   in-place before `identityMatches` executes.

3. **`/proc/<pid>/cmdline` is untrusted user-writable memory:**
   - Linux reads `/proc/<pid>/cmdline` from the target process's writable userspace
     stack (`mm->arg_start .. mm->arg_end`), and `argv` is arbitrary upon `execve`.
     Relying on `procArg` / `procArgs` as a security boundary violates basic kernel
     security invariants.

4. **Missing parent validation (`parent_cwd`, `parent_ppid`, unpinned `ppid`) and
   reparenting to PID 1 (`runit`):**
   - `identityMatches` (`761-780`) never verifies `parent_cwd`, never opens a `pidfd` or
     checks `starttime` on `ppid`, and never verifies that `runsv`'s own parent
     (`parent_ppid`) is the real `runsvdir` process.
   - For `.stage` (`761-764`), `identityMatches` checks `parent_exe == "/usr/bin/runit"`
     and `arg0 == "3"`. On a running Werewolf VM, PID 1 *is* `/usr/bin/runit`. Any
     process whose parent exits before it is automatically reparented by the kernel to
     PID 1 (`/usr/bin/runit`), and `arg0` (`argv[0]`) is caller-controlled on `execve`.

5. **Native TPM-enabled boots still lend a raw read-write `/victim` mount into the
   shared namespace (`201-210`):** The audited authorization path permits the supervised
   updater to borrow the slot filesystem when the boot carries a sealed release
   identity. On a native Secure Boot + TPM machine (`werewolf.release=...`, such as the
   live VM), `ctx.release` is `true`. That re-enables lending the raw `victim` mount
   word at `/run/werewolf/mnt/victim` in the shared mount namespace
   (`cmd/slot-update/slot.zig:393-396`)! While mounted (or via the `.updater`
   impersonation above), any confined root process has direct read-write access to
   `/victim/werewolf/a/root.erofs`, `/victim/werewolf/b/root.erofs`,
   `/victim/werewolf/boot-state/state.*`, and `/victim/werewolf/data`.

6. **Trivial 8-connection exhaustion DoS (`max_conns = 8`) & FIFO hang (`132-155`,
   `1130-1145`):**
   - `accept()` admits any `uid == 0` client into the 8-slot `conns` array without
     authenticating the service or setting a read timeout. A confined root process
     opening 8 idle sockets to `/run/werewolf/mount-broker.sock` permanently starves
     `slot-keep` (`"no busy: too many askers\n"`), preventing `/run/werewolf/committed`
     and causing `stage0`'s `deadman` timer to roll back a healthy boot.
   - In `copyChecked` (`1138-1143`), `mount-broker` opens
     `/data/svc/autoupdate/work/slot/*` with `O_RDONLY | O_NOFOLLOW` (no `O_NONBLOCK`,
     no `fstat` `S_IFREG` check, and intermediate path components in `/data` are
     resolved without `RESOLVE_NO_SYMLINKS`). `O_NOFOLLOW` only rejects symlinks, not
     FIFOs (`mkfifo`). If confined root replaces a staged file on `/data` with a FIFO,
     `openat` blocks the single-threaded `mount-broker` forever.

### 1.2 Unauthenticated Operator Control Socket (`update-control.sock`) & Runit FIFOs
- **Severity:** High
- **Location:** `cmd/slot-update/control.zig:31-76`, `cmd/slot-update/slot.zig:338-378`,
  `cmd/slot-update/images.zig:176-194`

1. `slot-update` listens on `/run/werewolf/update-control.sock` and accepts `check`,
   `outcome`, and `try [HASH]` from any `uid 0` peer (`SO_PEERCRED` `cred.uid == 0`).
2. Sending `"try"` (with `expected == null`) invokes `slot.tryOther(&u, null)` inside
   the genuine supervised `slot-update` daemon. `tryOther` calls `images.verifyOther(u,
   null, true, true, false)` with `rollback = true`—explicitly skipping `fresh(u,
   image)` (`images.zig:191`)—and then calls `broker.espArm()` (as the authorized
   `slot-update` service!) and `/usr/bin/reboot`. Any confined root process can
   therefore use `update-control.sock` to bypass `mount-broker` authentication, bypass
   `image-floor` anti-rollback checks (when TPM retirement is not active), arm an older
   slot, and immediately reboot the machine.
3. Furthermore, `/run/werewolf` and `/run/runit/supervise.*` are writable by any `uid 0`
   process in the fence: confined root can `unlink` `/run/werewolf/mount-broker.sock` or
   `/run/werewolf/update-control.sock` and bind a fake listener, or write to
   `/run/runit/supervise.*/control` to stop/restart supervised services.

**Remediation:**
- Delete `authorizeService`, `serviceIdentity`, `identityMatches`, and `task-links`.
  Replace `/run/werewolf/mount-broker.sock` with anonymous `socketpair(AF_UNIX,
  SOCK_SEQPACKET | SOCK_CLOEXEC)` descriptors created by `init` before `fence` and
  inherited strictly by the authorized services.
- Move `boot-state` (`state.0`/`state.1`) writes inside `mount-broker` on a detached
  mount FD—just like `esp-*` and `slot-*`—so `Word.victim` is never mounted into the
  shared namespace on native machines.

## 2. Live VM vs. Code Reality (`howl ssh`)

### 2.1 Disk Builder Leaves Critical `/victim` Boot Files Owned by Host Builder UID
- **Severity:** High
- **Location:** `cmd/howl/disk.zig:255-310`, `cmd/posture/files.zig`

Inspecting `/victim/werewolf` on the running VM via `howl ssh` revealed:
```text
/victim/werewolf:
drwxr-xr-x    2 0        0             4096 Jan  1  1980 a
drwxr-xr-x    2 501      20            4096 Jan  1  1980 boot-state
drwxr-xr-x    4 0        0             4096 Oct 13 19:55 data

/victim/werewolf/a:
-rw-r--r--    1 501      20             120 Jan  1  1980 cmdline
-rw-r--r--    1 501      20            5728 Jan  1  1980 image.json
-rw-r--r--    1 501      20             512 Jan  1  1980 image.json.sig
-rw-r--r--    1 0        0         20299776 Jan  1  1980 root.erofs

/victim/werewolf/boot-state:
-rw-r--r--    1 501      20             432 Jan  1  1980 state.0
```

And inside `/etc/passwd` on the same VM:
```text
t:x:501:501::/data/home/t:/bin/ash
```
Why? Look at `cmd/howl/disk.zig:298-305`:
```zig
    // mke2fs -d keeps the builder's owners and times. A file left with the
    // builder's uid would belong to whoever has that uid on the machine.
    var cmds: std.ArrayList(u8) = .empty;
    for ([_][]const u8{ "/werewolf", "/werewolf/a", "/werewolf/a/root.erofs" }) |p| {
        for ([_][]const u8{ "uid", "gid" }) |f| try cmds.print(b.gpa, "sif {s} {s} 0\n", .{ p, f });
        for ([_][]const u8{ "atime", "ctime", "mtime", "crtime" }) |f|
            try cmds.print(b.gpa, "sif {s} {s} {s}\n", .{ p, f, epoch });
    }
```
The comment states the exact bug, and then line 301 hardcodes a 3-element array instead
of walking the staged `root` tree! When `boot-state/state.0` and
`a/{cmdline,image.json,image.json.sig}` were added on lines 255–278, they were omitted
from the `debugfs` fixup list.
- Worse, `posture`'s `files-known-owners` check (`cmd/posture/files.zig`) only walks `/`
  (`xdev`) and never inspects `/victim`, reporting `✅ File owners known` while the TPM
  boot-state journal is owned by UID 501.

### 2.2 System Root Services Run Without `leash`, Holding Capabilities, `NoNewPrivs: 0`
- **Severity:** High
- **Location:** `cmd/fence/fence.zig`, `cmd/init/init.zig`

Checking `/proc/<pid>/status` on the live VM for `runsvdir` (PID 654), `slot-update`
(PID 662), and `sshd` (PID 667) shows:
- `Uid: 0 0 0 0`
- `CapEff: 00000024b5c4cdff` (retains `CAP_CHOWN`, `CAP_DAC_OVERRIDE`,
  `CAP_DAC_READ_SEARCH`, `CAP_FOWNER`, `CAP_KILL`, `CAP_SETGID`, `CAP_SETUID`,
  `CAP_SYS_CHROOT`, `CAP_SYS_BOOT`, `CAP_SYS_TIME`, `CAP_AUDIT_WRITE`, `CAP_SETFCAP`)
- `NoNewPrivs: 0`
- `Seccomp_filters: 1` (only `init`'s machine-wide seal; none of
  `/etc/sv/{autoupdate,cloud-metadata,posture,power-button,slot-keep,sshd}` run under
  `leash`).
- Because `/etc/{passwd,group,shadow,hosts,hostname}` are symlinks into
  `/run/werewolf/*`, and every root process inside `fence` has write access to
  `/run/werewolf`, **any compromised root service can directly rewrite
  `/run/werewolf/passwd` and `/run/werewolf/shadow`**, create `/run/werewolf/committed`
  (disarming `deadman` on a broken boot) or `/run/werewolf/rollback-checked` (spoofing
  `posture`), and overwrite `/run/werewolf/posture.json`.

## 3. Updater, Package Verification & Composition Weaknesses

### 3.1 Confined Root Shares `/data/svc/autoupdate` With the Updater (State Poisoning)
- **Severity:** High
- **Location:** `cmd/slot-update/slot.zig:51-229` (`buildSlot`), `433-495`
  (`installEsp`), `518-573` (`apkAdd`), `cmd/slot-update/images.zig:13-96`

`slot-update` stores all of its working state under `/data/svc/autoupdate` (`work_dir`,
`cache_dir`, `image-floor`, `cve-tiers.json.serial`, `bad`, `pending`, `attempt`).
Because `/data` is writable by any confined root process in `fence` and is mounted
without `nosymfollow`:
1. **Unauthenticated staging tree during local package builds (`u.image == null`):** In
   `buildSlot()` (`slot.zig:51-229`), `slot-update` extracts packages into
   `/data/svc/autoupdate/work/root` and builds `/data/svc/autoupdate/work/stage0` before
   running `mkfs.erofs` and `verity.build`. Then `installEsp()` (`slot.zig:434,
   480-486`) simply calls `signed.hashFile()` on whatever files are sitting in
   `/data/svc/autoupdate/work/slot/*` and sends those digests to `mount-broker`. Any
   confined root process can modify files in `work/root` before `mkfs.erofs`, modify
   `work/stage0/init` before `writeCpio`, or replace
   `work/slot/{vmlinuz,stage0.zst,root.erofs}` before `signed.hashFile()`, and
   `slot-update` will hash and install the attacker's payload into the next slot.
2. **Incomplete `reclaim` and multi-index confusion in `checkCache` (`slot.zig:627-673,
   735-758`):**
   - `reclaim()` chowns cached files left by `_update` (`uid 69`) back to root without
     checking `st_nlink == 1`, without ensuring no open writable FD is still held by a
     lingering `_update` process, and calls `linux.fchmodat(d.handle, file, 0o644)` with
     `flags = 0` (no `AT_SYMLINK_NOFOLLOW`).
   - `checkCache()` loops over *all* `APKINDEX.*.tar.gz` files in `cache` and unions
     their records into `idx`, while `prune()` (`719-730`) only deletes `.apk` files and
     never removes stale `APKINDEX.*.tar.gz` files.
3. **`stripSetid` skips directories (`slot.zig:774`):** `if (e.kind != .file) continue;`
   leaves setgid (`0o2000`) / setuid (`0o4000`) bits intact on directories in the built
   root image.
4. **Anti-rollback floor and `bad`-list poisoning on `/data` (`images.zig:13, 50-66,
   96`):** Confined root can append upcoming release build IDs to
   `/data/svc/autoupdate/bad` to permanently block all future security updates
   (`error.ImageRolledBack`), or delete `/data/svc/autoupdate/image-floor` on machines
   without TPM retirement.

### 3.2 `lib/apk.zig`: `u16` Overflow Panic in `signatureSegment`, Parser Differentials
- **Severity:** Medium
- **Location:** `lib/apk.zig:20, 41-49, 88-116, 121-161, 171-190, 291-315, 342-387`

1. **`@intCast(body.len)` to `u16` panic (`292, 310, 314`):** `max_signature` is `65536`
   (`64 << 10`), and `sig.len <= max_signature` is permitted at line 292. Line 310
   computes `body = tar[0 .. 512 + std.mem.alignForward(usize, sig.len, 512)]`. Whenever
   `sig.len` is between `65024` and `65536`, `body.len` is `65536` or `66048`, which
   overflows `u16` and panics at `const len: u16 = @intCast(body.len);`.
2. **Tar and `.PKGINFO` parser differentials between `lib/apk.zig` and `apk-tools`:**
   - `verified()` (`112-114`) inspects only the *first* tar entry named `"APKINDEX"` and
     ignores subsequent entries; `control()` (`179-185`) checks only the *first*
     `.PKGINFO` entry and the *first* `datahash = ` line, without verifying that
     `pkgname` and `pkgver` in `.PKGINFO` match the `APKINDEX` record.
   - `parseRecords()` (`129-144`) allows duplicate `P:`, `V:`, `C:`, or `D:` lines in
     the same stanza (last-one-wins) and does not reject `/` or `..` in `P:` or `V:`.
   - `parseKey()` (`353-377`) does not verify `spki.slice.end == bytes.len` (allowing
     trailing bytes) or that the RSA `AlgorithmIdentifier` parameters field is ASN.1
     `NULL`.

### 3.3 `cve.zig`: `VersionReader.fail()` Sentinel Collision & Unchecked Tar Checksums
- **Severity:** Medium
- **Location:** `cmd/slot-update/cve.zig:207-237` (`readVulnsTar`, `tarSize`), `370-455`
  (`VersionReader`, `apkOrder`)

1. **Sentinel collision (`-1`) in `apkOrder` (`405-446`):**
   - `VersionReader.fail()` returns `-1` (`432`) on an invalid version token.
   - However, `VersionReader.token()` also returns negative values for valid tokens:
     pre-release suffixes (`_alpha` = `-4`, `_beta` = `-3`, `_pre` = `-2`, `_rc` = `-1`
     at line 407) and leading-zero numbers (`.01` = `-1`, `.001` = `-2` at line 389).
   - Because `apkOrder` checks `if (xv != yv) return std.math.order(xv, yv);` *before*
     checking `x.t == .invalid` or `y.t == .invalid`, a malformed version string (`-1`)
     compares **greater than** `_alpha`, `_beta`, `_pre`, and `.001`, and **equal to**
     `_rc` and `.01`! Since `backwards()` (`slot-update.zig:1344-1364`) uses `apkOrder`
     to reject package/kernel downgrades, a malformed version can bypass downgrade
     detection.
2. **Duplicate tar parser missing checksum and magic verification (`207-237`):** Unlike
   `lib/apk.zig:401-409`, `cve.zig`'s `readVulnsTar` / `tarSize` never verifies the tar
   header checksum (`header[148..156]`) or `ustar` magic.

### 3.4 `compose.zig` & `package.zig`: Symlinks, `..` in `prune`, Newline Injection
- **Severity:** Medium
- **Location:** `lib/compose.zig:241-268` (`lay`), `786-803` (`prune`),
  `lib/package.zig:88-191` (`pack`)

1. **`lay()` follows symlinks in the destination tree (`compose.zig:252-266`):** `lay`
   copies form trees into `ro` using `from.copyFile(e.path, into, e.path, io, .{})` and
   `into.createDirPath(io, e.path)` without `RESOLVE_IN_ROOT` or unlinking existing
   symlinks at intermediate/leaf paths.
2. **Interior `..` bypass in `compose.prune` (`compose.zig:791-798`):** `prune` only
   checks `startsWith` and `endsWith` for `./`, `../`, `/.`, `/..`, missing interior
   traversal segments like `usr/../../etc/passwd`.
3. **Newline injection in `package.pack` (`package.zig:117-189`):** `pack()`
   interpolates `info.name`, `info.version`, `info.description`, `info.url`,
   `info.license`, `info.depends`, and `info.provides` into `.PKGINFO` and `APKINDEX`
   stanzas without rejecting `\n` or control characters.

### 4. Early Boot, Confinement & TPM/Cryptographic Subsystems

### 4.1 `fence.zig`: Stateless FIB Rules as a "Firewall" Allow Source-Port Spoofing
- **Severity:** Critical
- **Location:** `cmd/fence/fence.zig:220-228, 318-329, 456-520, 580-609, 805-811`

1. **Source-port spoofing bypasses inbound firewall rules (`580-592, 805-809`):**
   ```zig
   for (p.connect[0..p.nconnect], 0..) |c, i| {
       if (c.proto == .icmp or c.any) continue;
       var seen = false;
       for (p.connect[0..i]) |earlier| {
           if (earlier.proto == c.proto and earlier.port == c.port and !earlier.any) seen = true;
       }
       if (!seen) rules.add(.{
           .priority = pref.in_allow,
           .action = FR_ACT_TO_TBL,
           .table = RT_TABLE_LOCAL,
           .proto = c.proto,
           .sport = c.port,
       });
   }
   ```
   `fence` attempts to implement a host firewall using **stateless Linux FIB routing
   policy rules (`RTM_NEWRULE`)** instead of stateful netfilter/nftables (`ctstate
   ESTABLISHED`). Whenever *any* service/user is allowed outbound connections to a port
   (e.g., TCP 443 for updates or UDP 53 for DNS), `fence` installs a global inbound FIB
   rule at `pref.in_allow` (priority 300) routing **all incoming packets with `sport ==
   c.port`** into `RT_TABLE_LOCAL`—regardless of connection state (`SYN` vs `ACK`) or
   destination port!
   - Any remote attacker who binds source port 443 (TCP) or 53 (UDP) completely bypasses
     `pref.in_drop` (priority 399) and can connect to **every** listening TCP/UDP socket
     on the machine.
   - Because Landlock (`LANDLOCK_ACCESS_NET_BIND_TCP`) only checks port numbers and not
     bind IP addresses, any `loopback` service that binds `0.0.0.0` or `::` (which the
     comment at line 806 claims is safe because *"No routing rule names a loopback
     port"*) is directly reachable from the external network by any packet with `sport
     == 443` or `sport == 53`.
2. **`connect ... tcp any` exposes the entire ephemeral port range (`32768..60999`) to
   unsolicited inbound SYN packets (`597-609`)** and passes `c.port = 0` to Landlock
   `connect_tcp` (`810-811`), whereas in Linux Landlock `0` is only valid for `BIND_TCP`
   (ephemeral bind), not `CONNECT_TCP`.
3. **Loopback isolation (`pref.loopback_refuse`, lines `456-501`) only blocks
   `127.0.0.0/8` and `::1/128`:** Local processes with `connect ... tcp any` can still
   reach local services bound to `0.0.0.0` or the primary NIC IP by connecting to the
   machine's own NIC IPv4/IPv6 address (hitting `pref.local_out` at priority 10).
4. **SSRF filter (`non_public6`, lines `220-228, 506-520`) omits IPv4-mapped IPv6
   (`::ffff:0:0/96`), SIIT (`::ffff:0:0:0/96`), and 6to4 (`2002::/16`),** and

### 4.2 `lib/seal.zig`: Service Filter Permanently Allows `execveat` on `exec_fd`
- **Severity:** High
- **Location:** `lib/seal.zig:365-393, 457-465, 480-529`, `cmd/leash/leash.zig:369-413`,
  `lib/sandbox.zig:205-230`

1. **`AT_EMPTY_PATH` in `execveat` only applies when `pathname` (`args[1]`) is `""`
   (`lib/seal.zig:457-465`):**
   ```zig

   if (per_service and !promises.contains(.exec) and exec_fd != null) {
       put(buf, &n, JEQ_K, 0, 6, number(.execveat));
       put(buf, &n, LD_W_ABS, 0, 0, 16); // seccomp_data.args[0], low word: fd
       put(buf, &n, JEQ_K, 0, 3, exec_fd.?);
       put(buf, &n, LD_W_ABS, 0, 0, 48); // seccomp_data.args[4], low word: flags
       put(buf, &n, JEQ_K, 0, 1, AT_EMPTY_PATH);
       put(buf, &n, RET_K, 0, 0, linux.SECCOMP.RET.ALLOW);
       put(buf, &n, RET_K, 0, 0, other);

   ```
   - In the Linux kernel (`fs/exec.c:do_execveat_common` / `getname_flags`),
     `AT_EMPTY_PATH` only executes the open file descriptor `fd` **if the user-space
     `pathname` pointer (`args[1]`) points to an empty string (`""`)**. Classic seccomp
     BPF cannot dereference user-space pointers and **never checks `args[1]`**. If a
     compromised service passes a non-empty absolute path (e.g.,
     `"/usr/lib/werewolf/leash"` or another Landlock-allowed binary) with `fd = exec_fd`
     and `flags = AT_EMPTY_PATH`, the kernel ignores `fd` and executes `pathname`!

     `dup2`/`dup3`/`fcntl(F_DUPFD)` are in `stdio` (`lib/seal.zig:60, 74`). Even with
     `pathname == ""`, a service without the `exec` promise can open any
     Landlock-allowed executable (`s.exec[0]`, `s.before` binaries, `service-config`,
     `leash`, or `sh-shim`), `dup2` it onto `exec_fd`, and call `execveat(exec_fd, "",
     argv, envp, AT_EMPTY_PATH)` with attacker-controlled `argv` and `envp`.
2. **Low-32-bit argument truncation across `lib/seal.zig` (`365-393, 459-462, 480-529`)
   and `lib/sandbox.zig` (`205-230`):** Every argument check loads only the low 32-bit
   word (`LD_W_ABS` at `16 + arg * 8`) without verifying that the upper 32 bits
   (`offset+4`) are zero. For 64-bit `unsigned long` kernel arguments such as
   `clone(unsigned long flags, ...)` (`lib/seal.zig:378, 527`) or `ioctl` `cmd`
   (`lib/sandbox.zig:205`), high-32-bit flags are invisible to the BPF filter.
